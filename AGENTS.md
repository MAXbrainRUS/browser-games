# Инструкция для агентов

Здесь собраны браузерные игры. Сайт публикуется на GitHub Pages
(https://maxbrainrus.github.io/browser-games/): сначала каталог, из него открывается игра.
На iPhone и iPad сайт добавляют на экран «Домой», и он работает как приложение, в том числе без интернета.

Обычная задача — **добавить игру** или **исправить существующую**. В обоих случаях меняется только
папка этой игры `games/<id>/`. Каталог, иконки приложения, офлайн-режим и проверки общие, их трогать не нужно.

## Как устроено

```
games/<id>/          одна игра = одна папка
  index.html         сама игра (обычно один файл: HTML + CSS + JS)
  game.json          название, описание и метки для карточки в каталоге
  icon.svg           иконка в каталоге (квадрат без скруглений, углы скругляет каталог)
  game.spec.mjs      проверки этой игры (Playwright); на сайт не попадает
  …                  картинки, звуки, свои .js/.css — по относительным путям
site/                общая часть: каталог, manifest, service worker, shared/game-kit.js
scripts/build.mjs    собирает dist/ и проверяет все игры
scripts/serve.mjs    локальный просмотр (npm run dev)
scripts/new-game.mjs заготовка новой игры (npm run new)
templates/game/      из чего делается заготовка
tests/               общие проверки для всех игр
```

`scripts/build.mjs` сам находит все `games/*/game.json`, рисует карточки каталога и список файлов для
офлайн-режима. Поэтому новая игра появляется в каталоге без правок где-либо ещё.
После слияния PR в `main` GitHub Actions собирает сайт и публикует его (`.github/workflows/deploy.yml`).

## Добавить игру

1. `npm install` (один раз), потом `npm run new -- <id> "<Название>"`.
   `<id>` — имя папки и часть адреса: латиница в нижнем регистре, цифры, дефисы (`find-pair`).
2. Напишите игру в `games/<id>/index.html` вместо примера-счётчика. Сохраните из заготовки: meta viewport,
   подключение `../../shared/game-kit.js`, ссылку «Игры» с `data-home`, сохранение состояния.
3. Заполните `game.json`: `title`, `description` (одна-две фразы, что делать в игре), `tags`
   (например, `"1 игрок"`, `"2–4 игрока"`, `"головоломка"`). Необязательное поле — `icon`, если иконка не `icon.svg`.
4. Нарисуйте `icon.svg`: квадрат 512×512, фон на всю площадь, крупный простой знак игры.
5. Опишите в `game.spec.mjs` настоящий ход игры: несколько действий и проверку результата
   (примеры: `games/cant-stop/game.spec.mjs`, `games/purple-shades/game.spec.mjs`).
6. Проверьте (раздел «Проверка») и откройте PR. В описании PR: что за игра, как играть, что проверено.

## Исправить игру

Меняйте только `games/<id>/`. Если меняется формат сохранённого состояния, старое сохранение на телефоне
игрока не должно ломать игру: проверяйте загруженное (`valid()`), а при несовместимых изменениях
смените ключ (`<id>.v1` → `<id>.v2`). Добавьте в `game.spec.mjs` проверку на исправленную ошибку.

## Требования к каждой игре

Игра должна нормально играться и на телефоне пальцем, и на компьютере мышью и клавиатурой.

**Экраны.** iPhone вертикально и горизонтально, iPad, компьютер. Без горизонтальной прокрутки.
Раскладка подстраивается под экран (`@media`, `clamp()`, `min()`, container queries), а не масштабируется целиком.
Высота экрана — `100dvh` (у `100vh` на iPhone часть уходит под панели Safari).
В `<meta name="viewport">` есть `viewport-fit=cover`, отступы от выреза и полоски «Домой» через
`env(safe-area-inset-*)`.

**Ввод.**
- Кнопки — `<button>` с обработчиком `click`: это сразу и палец, и мышь, и Enter/пробел.
- Перетаскивание — через Pointer Events (`pointerdown/move/up`), у перетаскиваемых элементов
  `touch-action: none`. И всегда есть запасной способ без перетаскивания: нажать на предмет, потом на место.
- Ничего важного только по наведению (`:hover`) — на телефоне наведения нет.
- Цели для пальца — не меньше 44×44 px.
- На игровых элементах `user-select: none` и `-webkit-touch-callout: none`, чтобы долгое нажатие
  не выделяло текст и не открывало меню.
- Клавиатура: основные действия доступны с клавиатуры, фокус виден (`:focus-visible`).

**Состояние.** iOS выгружает страницы в фоне, поэтому партия сохраняется в `localStorage` после каждого хода:
ключ `<id>.v1`, `try/catch` вокруг чтения и записи, проверка загруженного. Где уместно — «Заново» и «Отменить».

**Оформление.** Интерфейс на русском, `<html lang="ru">`. Светлая и тёмная тема (`prefers-color-scheme`)
или одна осознанно выбранная; `<meta name="theme-color">` в цвет фона. Учитывайте `prefers-reduced-motion`.
Звук включается только после нажатия игрока (иначе iOS его не пустит), и его можно выключить.

**Без внешних зависимостей.** Всё лежит в папке игры. Исключение — Google Fonts с системным
шрифтом в запасе: офлайн-режим их кэширует. Скрипты и картинки с чужих сайтов без интернета не загрузятся.

**Обязательная обвязка** (её проверяет `npm run build`, без неё сборка упадёт):
- `game.json` с `title` и `description`;
- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` и `<title>`;
- `<script src="../../shared/game-kit.js" defer></script>`;
- только относительные пути (`icon.svg`, `./img/a.png`, `../../`), не `/img/a.png`: сайт живёт в подпапке `/browser-games/`.

Возврат в каталог — ссылка `<a href="../../" data-home>Все игры</a>` на видном месте. Если её нет,
`game-kit.js` сам добавит плавающую кнопку в угол (угол: `data-home-position="top-right"` на теге `<script>`).
Ссылка должна быть в разметке к концу загрузки страницы.

## Проверка

```sh
npm install                     # один раз
npm run dev                     # http://localhost:8080/browser-games/ , печатает и адрес для телефона в той же Wi-Fi
npm test                        # все проверки
npm test -- -g <id>             # только одна игра (общие проверки + её game.spec.mjs)
npm test -- --project=iphone    # один экран: desktop, iphone, iphone-landscape, ipad, safari-iphone, safari-ipad
```

`npm test` для каждой игры на каждом экране проверяет: страница открывается без ошибок в консоли,
помещается по ширине, есть видимая ссылка в каталог и она работает; плюс проверки из `game.spec.mjs`.
Отдельно проверяется, что каталог работает офлайн.

В тестах используйте `press(locator, hasTouch)` из `tests/helpers.mjs` — на телефоне это касание, на компьютере клик.
Перетаскивание пальцем — `touchDrag()` (только Chromium), мышью — `locator.dragTo()`.

Скриншоты всех игр на всех экранах сохраняются в `screenshots/<экран>/<id>.png`.
**Посмотрите на них перед PR**, особенно `iphone` и `iphone-landscape`: тест проверяет, что всё
открылось, но не то, что выглядит хорошо. В PR те же скриншоты прикладываются к проверке (артефакт `screenshots`).

Экраны `safari-*` (движок WebKit, как в Safari на iPhone) запускаются, если WebKit установлен
(`npx playwright install webkit && npx playwright install-deps webkit`). В GitHub Actions они запускаются всегда.

## Общая часть

Меняется редко и отдельными PR, не вместе с игрой:
- название и иконка приложения — `site/index.html`, `site/manifest.webmanifest`, `site/icons/`;
- вид каталога — `site/index.html`, `site/catalog.css`, `site/catalog.js`;
- офлайн-режим — `site/sw.js` (сначала сеть, при её отсутствии — кэш; версия кэша считается при сборке);
- то, что получает каждая игра, — `site/shared/game-kit.js`.
